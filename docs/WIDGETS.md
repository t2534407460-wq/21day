# 桌面卡组与今日抽屉（0.10.1）

状态：已修改待测试；目标设备为小米15 / 澎湃OS3。澎湃OS4升级后另按用户反馈变更。

## 0.10.1 可见尺寸修正

用户的澎湃OS3截图中，2×2分配区域比正方形更高，2×1也高于系统步数/电量卡。格数只决定桌面占位，原match_parent背景会铺满非等边格子。现在在Android 12及以上按宿主报告的内容空间设置背景尺寸：2×2取短边作为边长，2×1保留宽度、高度为宽度的38%且不超出可用高度；原圆角保留。调整的是可见卡面，系统占用格数不变，外部对齐仍由桌面排版决定。

优先使用OPTION_APPWIDGET_SIZES为每种可用尺寸生成RemoteViews；仅报告min/max的桌面使用横竖屏尺寸回退。旧Android 9—11保留原布局，不调用新尺寸API。切换尺寸时显式恢复标题/提示/按钮样式，再应用紧凑布局，避免视图复用遗留隐藏状态。数据卡极矮时用单行显示，编辑入口保留。依据：[Android响应式小部件布局](https://developer.android.com/develop/ui/views/appwidgets/layouts)。覆盖更新会沿原刷新链重绘，澎湃OS3旧组件缓存行为仍需实机验收。

## 0.10.0 新增尺寸

- **数据卡 2×1**：选择一个已有习惯，显示今日总量/尚未记录/计时中；点正文打开该习惯抽屉，点铅笔更换习惯。Android标准入口提供，澎湃OS桌面可承载；不冒充小米中心已审核的2×1规格。
- **打卡按钮 2×2**：次数、计时、每日确认采用“点按准备→卡片内确认”，直接在桌面写入，不打开主界面。15秒内有效；确认态用暖色区分，可取消；过期按钮最多撤销准备，不能直接记账。最小尺寸隐藏底部提示，保留按钮和标题入口。
- 每个小卡片独立选一个习惯，按区间/次数/每日/手填写明分类；次数+1、计时开始/结束、断崖式零支明确确认。未执行日与已确认日不能重复打卡；手填仍需打开填写。
- 用户于2026-10-04明确选择上述卡片内二次确认，替代2×2桌面业务长按设想。原App和大卡组抽屉650ms长按保留。
- 新增 `HyperOsCheckWidget` 小米专用2×2声明，原生编辑URI、独立进程、曝光刷新、ID迁移；0.10.1布局修正将miuiWidgetVersion从2递增为3。Android `CheckWidget` 保留实际可添加入口。小米中心**未提交、未收录**，安装APK本身不能解除截图中的“正在适配”。
- 原大卡组身份与关闭首尾循环的空白修正保留。原数据、计时、作息和提醒不迁移重置。

## 小米中心接入状态

官方当前应用小部件技术规格列2×2、4×2、4×4，最新设计规范同样列这些手机规格。应用及组件需通过小米商店/小部件平台审核，审核前只能在测试环境体验中心入口。2×1交付为Android数据卡，不伪造中心支持。

本轮已完成工程侧小米专用2×2及原卡组配置适配；用户已确认尚未申请小米开发者账号或上架应用，未进行上传、邮件联系或审核申请。可提交资料见 [小米接入清单](XIAOMI_WIDGET_SUBMISSION.md)。OS3实机中心展示、桌面尺寸和负一屏迁移仍待验收，OS4待用户升级后另提需求。

核对日期2026-10-04：[技术规范](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=1584)、[设计规范](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=1664)、[接入问答](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=1591)、[提交流程](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=1588)。Android标准小部件只支持点击与纵向滑动等受限交互，不提供任意View触摸监听；[交互限制](https://developer.android.com/develop/ui/views/appwidgets/overview)。

## 使用

- 今日页点「打卡抽屉」，左右滑动卡片或使用上一张/下一张；分区筛选区间计时、次数打卡、每日确认与手填。选择习惯只控制展示，不删数据、不停原提醒。
- 在桌面组件列表添加「廿一 · 打卡卡组」。每个实例可选择不同习惯，选择是否显示作息。组件内上下拖动切卡，第一张/最后一张为边界，反向滑动切回；保留StackView的无障碍滚动操作；「编辑」重新配置。
- 小米专用组件为「廿一 · 澎湃卡组」。平台收录/审核与系统版本决定它是否出现在小米小部件中心；当前没有提交小米商店审核，仍提供Android组件入口。
- 桌面长按由系统用来移动和编辑。点卡片进入独立抽屉，再持续长按打卡，短按不计数；计时长按开始/结束，次数每次长按只加1，需松开后再按。不能宣称桌面宿主本身支持650毫秒长按业务按钮。
- 原大卡组目标4×4（用户澎湃OS3网格显示4×3，实际占格由桌面决定）；旧的小尺寸组件显示打开抽屉入口，拉高后可显示完整叠卡。删除组件不删除习惯。

休息日的作息卡显示「参考起床」与「自然醒 · 不响起床闹钟」。睡前到点提醒/锁屏保持；工作日显示原起床安排。

## 0.9.2返回空白修正

旧版`loopViews=true`会在两张卡片循环时使用0—9的内部窗口位置。已在原0.9.1包复现：从第一张反向滑到「戒烟」，内部位置9，点开后返回刷新，卡数仍为2但当前卡为空；与用户截图一致。Android AdapterViewAnimator.refreshChildren只为小于实际卡数的窗口位置取新视图，循环窗口的其余位置被清空。

仅将widget.xml的loopViews改为false，使用系统已有首尾边界；上下切卡与回到原选中卡保留，不强行重置到第一张，不更改刷新/数据存储/跨进程快照。主应用抽屉的左右切卡和前后按钮保持原逻辑。升级后的旧桌面组件恢复、厂商缓存与渲染仍需用户在澎湃OS3确认。

## 0.9.1视觉调整

根据用户澎湃OS3截图，原卡面与底座明度过近，背卡轮廓融合，名称与记录之间留白过多。新卡组使用深绿底座，卡面按顺序明暗交替，加细边线和4dp底部阴影；深浅模式分别配色，不恢复球体高光。类型在左、序号在右，名称和记录量集中展示，目标单列，底部分隔线后的操作入口保持原功能。小尺寸自动压缩字号并合并目标，大字体和小尺寸需检查裁切。

## 实现与边界

- RhythmWidget保留旧组件身份；HyperOsWidget增加miuiWidget、miuiWidgetRefresh、20000ms曝光间隔、miuiEditUri编辑入口；application级miuiWidgetVersion初版为1，0.10.1递增为3。
- HyperOsWidget与CardWidgetService运行在`:widgetProvider`，Application在该进程跳过主应用初始化。所有习惯写操作留在App进程；组件读取原子写入的本机显示快照，避免跨进程SharedPreferences缓存。
- 快照不含API Key、验证点、聊天或自由备注；按刷新时当前日期计算显示，跨日不把昨天记录显示为今日。无网络、无推送服务。主App在作息/习惯/计时/选择变化时更新；系统周期刷新与小米曝光刷新补充显示更新。
- 深色模式采用values-night资源，组件背景使用android:id/background，保留系统圆角裁剪和布局伸缩。
- 桌面使用StackView和RemoteViews，不宿主其他应用的组件；不是系统级OS4卡组API。通用模拟器不能验证小米负一屏收录、系统拖拽动画或具体省电策略。
