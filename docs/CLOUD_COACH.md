# DeepSeek 作息与习惯复盘（0.8.0）

状态：**已修改待测试**。用户因安装和模型存储体积较大，将原本地离线要求改为固定 DeepSeek 云端，在 App 内填写自己的 API Key。原本地版说明保留于 [LOCAL_COACH.md](LOCAL_COACH.md)，不再代表当前行为。

## 使用

1. 覆盖安装 0.8.0，进入「变化 → 打开作息助手」。无需卸载旧版，无需模型下载。
2. 在 [DeepSeek 官方平台](https://platform.deepseek.com/api_keys) 创建自己的 API Key，在「设置 → AI 助手」填写并保存，聊天内设置也有跳转入口。密钥保存本身不验证接口；已开启的到期自动复盘会使用该密钥请求。
3. 在底部输入框直接聊天、连续追问，或点击麦克风入口打开键盘，再点键盘麦克风使用输入法语音；识别文字可以修改，需手动发送。今日/近7天复盘是快捷入口。补记时先点“补记”，选参考日期，再输入或口述作息。账户余额、网络和服务状态决定请求能否成功；费用按 DeepSeek API 账户结算。
4. 补记核对日期、原值和新值，确认才保存。未确认、取消、失败或离开不写日常记录。自述上床/起床时间不生成睡前打卡或醒后验证，既有验证时间戳与新睡前状态字段保持不变。
5. 0.5.0 按用户要求移除睡眠接入及发送开关。总结使用本机作息和睡前问答统计；旧总结文本继续保留，不再读取、发送 Health Connect 内容。

## 0.6.1 小米语音兼容修正

用户在小米上已授权，但系统语音弹窗仍提示“似乎出错了呢(2)”和“系统语音引擎需要您的授权”；用户明确反馈输入法语音正常。0.6.1默认麦克风入口改为聚焦输入框、显示键盘，提示点击键盘自身的麦克风，避免反复进入不可用的系统弹窗。App不能代替输入法点击录音按钮，也不因此申请独立录音权限。

助手设置的“优先使用输入法语音”默认开启并记住选择；关闭后保留原系统弹窗方式。系统请求返回非成功结果时区分结束/无匹配/客户端/服务端/网络/音频错误，并提供“改用输入法语音”入口。厂商弹窗编号无法单凭截图等同于标准错误码；没有确认小米引擎内部授权失败的具体原因，也不宣称修复了外部引擎。

以下标准RecognizerIntent说明仅针对手动选择系统语音的模式；普通输入法文字始终沿用输入框及手动发送流程。

## 聊天与语音

- 页面使用项目已有奶白、浅绿和深绿样式，消息区独立滚动，底部输入框跟随键盘。总结直接进入消息列表，右上角历史入口保留原有今日/7天报告与来源、过期提示。
- 手机通过标准 `RecognizerIntent.ACTION_RECOGNIZE_SPEECH` 返回中文识别文字。取消或空结果保留原输入；成功追加到输入框，聊天最多2000字、补记最多300字，不自动发出。没有兼容服务或权限不可用时显示输入法语音替代提示。
- 识别界面和联网行为由手机语音服务提供；不额外下载本地模型、不向DeepSeek发送录音、廿一不申请独立录音权限。本轮模拟器已能启动识别界面；小米15识别服务可用性和准确率需真机测试。不是自动播放回复的语音通话。
- 一般聊天不修改作息；保存自述继续走补记预览和确认。取消补记把原话放回输入框便于修改。网络失败/停止显示手动重试，不自动追加重复提问，切后台断开接收。

## 接口与数据

- 固定 `https://api.deepseek.com/chat/completions`、`deepseek-flash`，遵循 2026-10-03 核对的官方文档。显式关闭 thinking，非流式，temperature=0，max_tokens=1024；补记使用 JSON Output。没有自动重试，避免失败后重复计费。
- 普通聊天使用system/user/assistant多轮消息，发送近7天统计和最近最多12条聊天消息，总正文约2万字符上限；不上传已有自由备注或验证点。旧聊天统计以最新统计为准，模型没有保存记录或改变计划的工具。
- 总结发送由代码计算的所选日期统计（计数、平均时刻、精神与原因分布），不上传已有自由备注、二维码/NFC 标识或整份备份；使用受控统计前10行，新增睡前困意、心情、原因与完成次数。
- 补记先由代码解析日期，最多3个日期，每日一次请求，只发送该日的本次描述与对应日期。模型输出校验字段白名单、日期、时间、枚举和该日原文字词；备注只保留原话。
- 不持续收集屏幕或其他应用对话；除明确开启的周期复盘外，不后台提交记录；睡前按三项回答加确认完成，醒后只有完整验证才能自动记录。请求内容由 DeepSeek 按其政策处理，App 不能保证服务端不留存。

## 本机存储与请求生命周期

- API Key 由 Android Keystore 的 AES-GCM 密钥加密，随机 IV，AtomicFile 原子保存到 `noBackupFilesDir/deepseek-key.json`。密钥不会放进 APK、提示词、总结、日志或 JSON 备份，系统备份/设备迁移仍按原规则排除应用数据。更换和移除密钥不清除日常记录或总结。
- 输入框隐藏密钥，不通过 rememberSaveable 保存输入；离开页面清空尚未保存的密钥文本。解密失败要求重新填写，不把网络或解密底层信息显示出来。
- 只向固定 HTTPS 端点提交，保持系统证书验证，禁止跟随重定向。连接15秒、读取60秒、整体每次请求90秒；回复上限128 KiB，正文最多8000字符。截断、拒绝、空白、非法结构不用于补记。
- 401/403、402、429、5xx、超时及断网分别提示，不向界面返回服务端原始错误体。聊天中停止或切后台取消并断开本机连接（自动复盘后台任务不受聊天页面切换影响）；已发送内容不可撤回，服务端可能继续处理或计费。
- `coach_chat`仅在本机保留最近60条消息和总结事实快照，不进入JSON备份。API Key仍单独加密。
- 今日/7天各保留最近一次总结、事实快照、时间和来源。旧本地版总结继续保留并显示来源为旧版本地模型；日期/记录变化后标记需要重新生成。总结与密钥不进入 schema=1/2 备份，已确认补记正常导出。

## 体积与兼容

移除 LiteRT-LM 原生依赖、独立 `:coach` 服务、模型导入下载界面及其专属许可文件。保留已验证的 Kotlin/Compose 2.2.21 编译插件，不无必要回退工具链。

升级后打开首页或助手，在 IO 线程取消旧 `coach_model` 中的 DownloadManager 任务，并删除应用自有 `no_backup/coach` 模型/缓存和外部私有目录 `coach/model.download`；失败下次重试。用户另外保存的导入源文件、电脑参考模型和旧安装包保留。清理不触及计划、日志、验证点和总结。

原平均时刻计算、跨午夜日期处理、补记冲突整批拒绝、正式闹钟60秒等待加5秒长按、扫码/NFC、夜间拦截和在线更新校验均保留。建议不自动改变计划、规则或闹钟。

## 0.8.0 自动复盘

- 周期：每周日00:00安排前一个周日至周六的数据，作息和各个习惯分别生成；每个习惯第21天结束后的00:00安排独立周期报告。采用手机当前时区，提前归档不足21天不产生21天报告。周报从启用功能当周起安排，不追补更早周报。
- 看板：习惯→复盘看板，或设置→习惯与复盘；每周/21天页签，按习惯切换，显示日期、记录日/达标日/计划日以及AI文字。等待、生成中、失败和成功分别显示，失败可手动重试。
- 设置：每周、21天两个自动开关默认开启，需已配置API Key且有对应周期。无Key不提交任务；关闭不删除历史报告。已发送内容无法撤回。
- 数据：周期内习惯名称、目标方向/单位、每日期目标与实际数值，未记录明确区分；作息使用已有受控统计。不上传自由备注、二维码/NFC、密钥或聊天。AI只给文字，不自动改计划。
- 执行：系统JobScheduler持久化联网任务，后台生成每份报告后安排下一份。已成功报告不重复请求；服务错误/超时标记失败，不无限重试，用户可手动重试。网络条件丢失/系统停止会等待恢复；进程中断可能无法确认服务端是否已处理，不能承诺服务端只计费一次。
- 00:00是安排时间，系统省电、网络、关机可能延后实际生成。重启与升级沿用原重排链。不是永久常驻服务，不绕过系统限制。
- 本机habit_reviews保存报告、生成时事实和时间，review_settings保存自动开关；不进入JSON备份。原聊天及last_1/last_7报告、Keystore密钥保留。
- 官方执行约束：[JobInfo.Builder](https://developer.android.com/reference/android/app/job/JobInfo.Builder)、[JobService](https://developer.android.com/reference/android/app/job/JobService)。请求模型、官方端点、响应限制和加密机制不改变。
