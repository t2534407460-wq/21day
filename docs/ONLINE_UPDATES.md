# 廿一在线更新

## 使用方式

0.9.1起，每次打开主界面或返回前台时检查GitHub；监听实际RESUMED生命周期，切后台取消本轮展示，回来重新检查。移除0.8.0的6小时冷却（当时失败也会进入冷却），避免发布新版本、联网失败或检查途中切后台后长时间不提示。没有新版或联网失败仍不转圈、不弹窗，有新版才询问下载；点稍后不下载，下次打开可再次提示。后台自启动与起床闹钟界面不弹更新。

也可在「设置 → 数据与更新 → 检查更新」手动检查。系统DownloadManager可在页面收起后继续下载，重新进入更新页查看进度或安装。旧0.8/0.9.0的冷却不会因发布新版而自动消失，本次可手动检查或下载APK覆盖安装，新的触发逻辑在安装0.9.1后生效。

点击安装前会校验文件大小、GitHub 提供的 SHA-256、包名、递增 versionCode、版本名及与已安装应用一致的签名。系统可能要求允许「廿一」安装应用，允许后返回再次点击安装，最后确认 Android 的安装对话框。无需卸载旧版；不能绕过系统确认静默安装。

无法连接 GitHub 或网络中断时可以重试。检查更新和下载安装包会向 GitHub 发送正常网络请求信息，不上传本地作息记录。取消记录或收起界面不等于取消系统下载。

## 后续发布约定

1. 在 `app/build.gradle.kts` 同时递增 versionCode 和三段式 versionName，例如 `0.2.1`。设置页从 BuildConfig 读取版本。
2. 使用原签名构建。当前版本延续本机 Android 调试签名以兼容早期已安装 APK；更换签名会被 Android 和应用更新校验拒绝。不要上传签名文件。
3. 安装包命名为 `21day-<version>-debug.apk`；Release tag 为 `v<version>`，必须发布为非 draft、非 prerelease，才会进入客户端稳定更新入口。体验版测试状态在说明中明确标注。
4. 完成必要验证并准备纯文本更新说明。版本号不能回退，已发布的同名安装包不能静默替换。
5. 使用 `tools/publish_release.py`。脚本从标准 Git Credential Manager 获取指定账号的现有凭据，仅在内存中使用，不打印或保存令牌；也不会修改本机 Git 的其他账号设置。

```powershell
python tools/publish_release.py --version 0.2.1 --apk releases/21day-0.2.1-debug.apk --notes releases/0.2.1-notes.txt
# 默认创建草稿并上传验证安装包；核对后才发布。
python tools/publish_release.py --version 0.2.1 --apk releases/21day-0.2.1-debug.apk --notes releases/0.2.1-notes.txt --publish
```

脚本核对登录账号、上传后的大小和 SHA-256。若同名资产内容不同则停止，不能覆盖已有下载。将发布设为 latest 后，客户端才会发现它。
